## Monolith 0.1.15 — page editing and security fixes

- Fixed dragging text on pages. Paragraphs, headings and lists move by their handles again; previously a drag silently cancelled and only databases could be moved.
- Fixed saving pages that contain links. Links made in the editor were rejected as unsafe, which stopped autosave for the whole page.
- Fixed a page address check that could stall the server on certain malformed addresses.
- Sign-in provider settings (Google, GitHub) can now be changed only by host administrators listed in `MONOLITH_AUTH_ADMIN_IDS`. Previously any signed-in account could change or remove them.
- Remote content requests now refuse private, loopback and cloud metadata addresses, including through redirects.
- Large file uploads through the gateway are no longer cut off after 30 seconds.

### Updating

Windows and macOS clients download authenticated updates automatically, then restart after two idle minutes in the background with edits saved. Server connection settings, saved sessions and drafts are kept outside application files. The previous version remains available for runtime rollback.

**Server administrators:** this release keeps the 0.1.14 schema fingerprint, so a server already on 0.1.14 updates automatically through the supervisor. Servers older than 0.1.14 still need the 0.1.14 planned migration first. To keep managing sign-in providers, set `MONOLITH_AUTH_ADMIN_IDS` to your account UUID in `env/.env.docker` and pass it to the `server` service (`MONOLITH_AUTH_ADMIN_IDS: ${MONOLITH_AUTH_ADMIN_IDS:-}`) in an existing Compose file. Providers that are already configured keep working without it.

The Windows installer is unsigned. The macOS application has an ad-hoc signature and is not notarized. macOS may request approval to use the saved Monolith Keychain item after an update. Update manifests and addon catalogs remain signed with the existing release keys.

## Add-on reliability and session recovery

- Windows and macOS add-ons now use the host's authentication, native connection, widget and query providers. This fixes the “useAuthContext must be used within an AuthProvider” failure.
- Rebuilt every downloadable add-on and widget with independent patch versions. Add-on bundles no longer carry competing copies of host libraries.
- Fixed shop installation of add-ons that include license notices. Every release package now passes the installer's validation before it can be published.
- Fixed URL-state adapter conflicts and missing desktop system translations.
- Provided the shared static renderer required by Redraw and add-on exports.
- Fixed hosted web session renewal through `/api/auth`. New refresh cookies work through both the gateway and the direct API, and obsolete cookie paths are cleared when a session is issued.
- Isolated session recovery and public-key request limits from expired background polling. Encryption failures now show an error and Retry instead of an endless loading screen.
- Added a production-build browser regression test covering a separately built add-on, sign-in context, authenticated native transport, widget state, translations and URL filters.

### Updating

Clients on 0.1.11 can download this release automatically and restart after two minutes in the background with edits saved. Existing update preferences, OptiPlex connections and local drafts are retained. The previous application version remains available for rollback.

Update installed add-ons from **Addons and Widgets** to receive their rebuilt packages. Existing data stays outside replaceable application files. A web session created before this release may need one sign-in to receive the corrected refresh cookie.

The Windows installer remains unsigned. The macOS app is ad-hoc signed and not notarized. Update manifests, add-on catalogs and download checksums remain verified.

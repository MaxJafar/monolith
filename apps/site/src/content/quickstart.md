Start with a running Monolith host and an account. If you are setting up a host, follow [Installation](/docs/installation) first. These steps describe the current development workspace; check [release availability](/docs/availability) when choosing a checkout or installer.

## 1. Give an idea a home

Open **Docs**, create a page and give it a title. Add a few paragraphs, a checklist or a heading. Organize related pages together and use references to connect ideas.

Reopen the page to confirm it saved. The [pages guide](/docs/pages) explains rich blocks, linked content and document recovery.

## 2. Turn it into a project

Open **Projects**, create a project and add a task with a clear next action. Choose a date when the work needs a place in your schedule.

Use a board or list to organize the project. **Actions** brings task records into Today, Upcoming, High priority and Completed views. **Calendar** brings dated work into your schedule. These are connected views of records, so changes should be made with the same care wherever you see them.

For structured information beyond tasks, create a [database](/docs/databases) with the properties and saved views you need.

## 3. Shape your dashboard and sidebar

Open **Dashboard** and use **Add widget** to choose a connected view. Enter layout editing to arrange and resize widgets.

In **Addons and Widgets**, select **Widgets**, open **Preview & configure**, adjust the available options and choose a supported placement. Calendar, Action agenda, Project focus and Training pulse provide focused views; some require an installed package or integration.

Use the **Sidebar** section for compact placements. Drag native section handles to reorder navigation, or use the keyboard and settings controls. [Widgets and dashboards](/docs/widgets) covers configuration and placement; [Your workspace](/docs/workspace) covers navigation.

## 4. Choose an optional tool

Browse the [collection](/addons) for full addons such as Atlas, Automations or Gym. Your host administrator installs packages; a workspace owner enables installed tools for that workspace.

Atlas adds a visual knowledge map. Automations connects workflow triggers and actions. Each tool has its own setup guide and may need a configured worker or external service.

## 5. Connect an agent when you need one

The [MCP and CLI bridge](/docs/agents) lets Codex, Claude Code, OpenClaw and other compatible clients work with accessible workspace records.

Build the bridge, sign in and generate configuration for your client. It starts in read mode; enable writing deliberately. The Agents addon is a separate tool for worker-backed assignments.

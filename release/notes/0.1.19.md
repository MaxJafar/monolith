## Monolith 0.1.19 — no manual restore button

- Settings → Updates no longer shows Restore previous version for the desktop app or the hosted server, so a previous build can't be reinstalled by accident. If an update fails to start or fails its health check, the previous version is still restored automatically.
- Includes the 0.1.18 Day, Week and Month calendar widget views, large page icons and Schedule & guests and project card improvements, the 0.1.17 page icon and cover popover, the 0.1.16 desktop window fixes and the 0.1.15 page editing and security fixes.

### Updating

Windows and macOS clients download authenticated updates automatically, then restart after two idle minutes in the background with edits saved. Server connection settings, saved sessions and drafts are kept outside application files. A client that was restored to an earlier build also updates to this release automatically.

**Server administrators:** this release keeps the 0.1.14 schema fingerprint, so a server on 0.1.14 or later updates automatically through the supervisor. Servers older than 0.1.14 still need the 0.1.14 planned migration first. If you are upgrading from 0.1.14, see the 0.1.15 notes for `MONOLITH_AUTH_ADMIN_IDS`.

The Windows installer is unsigned. The macOS application has an ad-hoc signature and is not notarized. macOS may request approval to use the saved Monolith Keychain item after an update. Update manifests and addon catalogs remain signed with the existing release keys.
